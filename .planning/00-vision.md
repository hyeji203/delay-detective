## 1. 한 줄 비전

> **"미루는 건 의지 문제가 아니라, 아직 해결되지 않은 마찰이다."**
>
> Delay Detective는 AI 인터뷰로 미루는 이유를 함께 발견하고,
> 실행 가능한 첫 걸음을 만들어주는 할일 관리 앱이다.

---

## 2. 문제 정의

### 2.1 핵심 문제
할일 앱은 넘쳐나지만, 사람들은 여전히 미룬다.

| 기존 앱의 가정 | 현실 |
|---|---|
| "리스트에 적으면 한다" | 적혀 있어도 손이 안 간다 |
| "알림을 보내면 한다" | 알림을 무시하거나 끈다 |
| "마감일을 보여주면 한다" | 마감이 보여도 회피한다 |

### 2.2 미루는 이유의 실제 구조

```
표면적 이유          실제 원인
─────────────────────────────────
"바빠서"        →   우선순위가 불명확해서
"하기 싫어서"   →   어디서부터 시작할지 몰라서
"나중에 해도 돼" →  실패가 두려워 시작을 회피
"귀찮아서"      →   태스크가 너무 크게 느껴져서
```

→ **미루는 건 의지 문제가 아니라 마찰(friction) 문제**

### 2.3 기존 앱이 못 하는 것

- Todoist, 노션, 애플 미리알림 → 할 일을 **기록**만 함
- 리마인더 → 알림을 **반복**할 뿐, 원인을 모름
- 어떤 앱도 "왜 이게 안 됐어요?"를 **묻지 않음**

---

## 3. 우리가 하는 것

```
기존 앱:
  태스크 등록 → 마감 알림 → 미룸 → 또 알림 (무한 반복)

Delay Detective:
  태스크 등록
    → 지연 감지 (자동: 마감일 초과 / 수동: 사용자 표시)
    → AI 인터뷰 ("뭐가 제일 막혀요?" 2~3턴 대화)
    → 원인 파악
    → 결과 출력:
        ① 공감 한 줄
        ② 원인 요약 한 줄
        ③ 소태스크 3개 이하 (15분 단위)
    → 첫 번째 소태스크 실행
```

## 4. 핵심 가치 제안 (Value Proposition)

| 대상 | 문제 | Delay Detective의 답 |
|---|---|---|
| 과제를 미루는 대학생 | 시작점을 모름 | AI가 "오늘 딱 15분만 할 수 있는 것"을 제시 |
| 개인 목표를 미루는 누구나 | 이유를 모름 | AI 인터뷰로 자신의 회피 패턴을 발견 |
| 할일앱을 써도 미루는 사람 | 기존 앱으로 해결 안 됨 | 기록 대신 대화로 접근 |

---

## 5. 타겟 사용자

**주 타겟**: 대학생 (과제·시험·프로젝트를 미루는 패턴)  
**부 타겟**: 개인 목표나 자기계발을 미루는 일반인

### 페르소나

> **수현 (22세, 대학생)**
> "할일 앱은 3개나 써봤는데 다 똑같아. 리스트만 쌓이고 결국 안 해."
> 마감 3일 전까지 미루다가 밤새 하는 패턴을 반복 중.
> 왜 미루는지 알면서도 시작이 안 됨.

## 7. 핵심 지표 (MVP 성공 기준)

- AI 인터뷰 완료율 > 70% (인터뷰를 시작한 사용자 중 끝까지 완료)
- 소태스크 실행률 > 50% (AI가 제시한 소태스크 중 완료 표시 비율)
- 오프라인 → 온라인 동기화 충돌 발생률 < 1%

## 8. 기술 스택 요약

| 계층 | 기술 |
|---|---|
| 프론트엔드 | Flutter (Dart) + Provider |
| 로컬 DB | Hive (오프라인 우선) |
| 클라우드 DB | Firebase Firestore (선택적 로그인 시 활성화) |
| 인증 | Firebase Auth (선택, 게스트 모드 지원) |
| AI | Anthropic API — Claude (인터뷰 + 분석) |
| 동기화 | Hive ↔ Firestore, Timestamp 기반 Last-Write-Wins |
