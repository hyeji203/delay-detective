## 논의 및 결정 사항

### 1. 플랫폼 선택

**논의**: Flutter / React Native / 네이티브 중 선택  
**결정**: **Flutter** 확정  
**이유**:
- 단일 코드베이스로 Android/iOS 동시 지원
- Firebase + Hive 패키지 생태계 성숙
- 이미 Flutter 프로젝트 세팅 완료 (세션 1)
- 6주 일정에 React Native 학습 곡선은 리스크

---

### 2. Q1 — 타겟 사용자

**선택지**: 대학생 / 직장인 / 일반인 / 대학생+일반인  
**결정**: **4번 — 대학생(주) + 일반인(부)**  
**이유**: 본인(대학생) 관점에서 구체적인 시나리오 작성 가능, 일반인도 포함해 범용성 확보

---

### 3. Q2 — 지연 감지 방식

**선택지**: 자동(마감일 기반) / 수동(사용자 표시) / 둘 다  
**결정**: **3번 — 자동 + 수동 모두**  
**이유**: 마감일을 설정한 태스크는 자동으로, 마감일 없이 막연히 미루는 태스크는 수동으로 표시

---

### 4. Q3 — AI 분석 방식

**선택지**: 챗봇 인터뷰 / 단일 입력 / 구조화 설문  
**결정**: **1번 — 챗봇 인터뷰 (2~3턴)**  
**이유**: 미루는 이유를 모르기 때문에 미루는 것. AI가 질문을 유도해야 사용자가 스스로 원인을 발견함. 단일 입력은 이 문제를 해결 못 함

---

### 5. Q4 — AI 분석 결과물

**선택지**: 세부 태스크 분해 / 공감+행동 1개 / 둘 다  
**결정**: **3번 — 공감 + 소태스크 둘 다 (순서 중요)**  
**확정 순서**:
  1. 공감 한 줄 (먼저 감정 수용)
  2. 원인 요약 한 줄
  3. 소태스크 3개 이하 (15분 단위)  
**이유**: 공감 없이 태스크 목록만 받으면 거부감 발생. 공감 → 행동 순서가 심리적으로 올바름

---

### 6. Q5 — 로그인 & 동기화

**선택지**: 필수 로그인 / 선택 로그인 / 로컬 전용  
**결정**: **선택 로그인 (게스트 모드 기본, 원하면 Firebase 동기화)**  
**구조**:
- 앱 첫 실행 → 바로 사용 (Hive 로컬)
- "동기화 켜기" → Firebase 로그인 → Firestore 연동  
**이유**: 가입 없이 바로 쓸 수 있어야 첫 인상이 좋음. 동기화는 선택지로 제공
