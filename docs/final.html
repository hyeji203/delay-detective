핵심 구현 — 오프라인-온라인 동기화

[오프라인] 사용자 조작 → Hive 즉시 저장 → sync_queue에 taskId 적재 [네트워크 복구] SyncService.flushQueue() → Hive.updatedAt vs Firestore.updatedAt 비교 → 더 최신 데이터 선택 (Last-Write-Wins)

Google 로그인 플랫폼 분기

if (kIsWeb) { signInWithPopup() // 웹: idToken 이슈 우회 } else { google_sign_in // Android: 네이티브 계정 선택 }
오프라인에서 변경한 내용은 sync_queue에 쌓아두고, 네트워크 복구 시 타임스탬프를 비교해서 더 최신 데이터를 선택합니다.

설치 가이드

웹 실행 시 --web-port 5000 고정이 핵심입니다. Google OAuth가 이 포트를 허용 목록에 등록했기 때문입니다.

문제원인해결
Firestore 중복 데이터 앱 실행마다 offline UID 재생성 Hive settings 박스로 UID 영속화

웹 로그인 후 화면 불변 signIn()이 웹에서 idToken 미반환 signInWithPopup()으로 전환

성능 최적화 & 코드 품질

⚡ 성능 최적화

  • Hive — RAM 수준 읽기, SQLite 대비 빠른 응답
  • Provider 범위 최소화 — 불필요한 위젯 리빌드 방지
  • Firestore Future 우선 — 리스너 최소화, 실시간 비용 절감
  • 릴리즈 APK 49.9MB — 이미지 없이 아이콘 폰트만 사용

🛡️ 코드 품질

  • 4-레이어 아키텍처 — 관심사 분리, 단방향 의존성
  • ChangeNotifierProxyProvider — uid 변경 시 Provider 자동 재생성
  • analysis_options.yaml — Flutter 공식 린트 규칙 적용
  • 민감 정보 보호 — keystore, .env 전부 .gitignore 처리
성능 측면에서 Hive가 핵심입니다. 오프라인 우선이라 네트워크 상태와 관계없이 즉각 반응합니다.
